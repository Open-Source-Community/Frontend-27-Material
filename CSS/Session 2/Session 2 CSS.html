1position: static (and how all values compare)

The position property decides how an element is placed in the page. static is the default: the element follows the normal flow and ignores top / right / bottom / left and z-index.

2relative + absolute: the classic pair

Give the parent position: relative to make it the anchor, then place the child with position: absolute. Without a positioned parent, the child would be placed relative to the whole page.

/* parent = anchor */ .card { position: relative; } /* child = placed inside the anchor */ .badge { position: absolute; top: -12px; right: -12px; } .note { position: absolute; bottom: 10px; right: 12px; }

3position: fixed

A fixed element is pinned to the viewport: it does not move when the page scrolls. Typical uses: navbars, chat buttons, cookie banners, progress bars.

.to-top { position: fixed; right: 22px; bottom: 22px; z-index: 999; } .progress { position: fixed; top: 0; left: 0; height: 4px; }
Live preview – this page already uses it

Scroll the page: the gradient progress bar at the very top and the round ↑ button at the bottom-right are both position: fixed.

A fixed element is removed from the flow, so give the page some top/bottom padding so it doesn't cover content.

4position: sticky

Sticky is a hybrid: the element behaves like relative until you scroll past a threshold (top: 0), then it "sticks" like fixed — but only inside its parent container. You must set at least one offset such as top.

.section-title { position: sticky; top: 0; /* required! */ background: #ffa100; }

5z-index & stacking

z-index controls which overlapping element is on top. Higher numbers win. It only works on positioned elements (anything except static) and on flex/grid items. If values tie, the element that comes later in the HTML is on top.

.a { position: absolute; z-index: 1; } .b { position: absolute; z-index: 2; } .c { position: absolute; z-index: 3; } /* on top */

6Pseudo-elements: ::before & ::after

::before and ::after create a virtual child element inside the selected element — before or after its content. They require the content property (use "" for decoration). They are inline by default, and often combined with position: absolute.

.quote::before { content: "\201C"; position: absolute; font-size: 64px; } .link::after { content: ""; position: absolute; bottom: -3px; width: 100%; height: 2px; transform: scaleX(0); } .link:hover::after { transform: scaleX(1); } .label::after { content: attr(data-badge); } /* reads an HTML attribute */ li::before { content: "\2714"; color: #ffa100; }

7Pseudo-classes

A pseudo-class (single colon :) selects an element in a certain state or position — hovered, focused, checked, first in its list… It styles the element itself; it doesn't create a new one like ::before does.

GroupPseudo-classesSelects…
User action:hover :active :focus :focus-visible :focus-withinMouse over, being pressed, keyboard/click focus, a parent containing the focus
Form state:checked :disabled :required :valid :invalidInputs by their state
Position:first-child :last-child :nth-child(n) :only-childElements by their place among siblings
Logic:not() :is() :has()Exclude, group or match by contents
.btn:hover { background: #ffd400; } /* mouse over */ .btn:active { transform: scale(.96); } /* while pressed */ .btn:focus-visible { outline: 3px solid #000; } /* keyboard focus */ .btn:disabled { opacity: .4; } .form:focus-within { border-color: #ffa100; } /* a child has focus */

:checked + pseudo-elements = custom toggle

Hide the real checkbox, then style the label's ::before (track) and ::after (knob) based on input:checked + label. The + is the adjacent-sibling combinator.

.switch input { position: absolute; opacity: 0; } .switch label::before { content: ""; background: #ccc; transition: background .25s; } .switch label::after { content: ""; background: #fff; transition: transform .25s; } .switch input:checked + label::before { background: #ffa100; } .switch input:checked + label::after { transform: translateX(20px); }
Order matters for link/button states: if you write :hover after :active, hover wins while pressing. Use the order link → visited → hover → focus → active.

Hover transition & staggered delay

Staggered with transition-delay – hover the squares:

.btn { transition: background .3s ease, transform .3s ease, box-shadow .3s ease; } .btn:hover { transform: translateY(-4px); } .box:nth-child(2) { transition-delay: .1s; } .box:nth-child(3) { transition-delay: .2s; }
Put the transition on the base state (not only on :hover) so it animates both in and out. Prefer animating transform and opacity for smooth performance.

9opacity

opacity goes from 0 (invisible) to 1 (fully visible). It affects the whole element including its children and text. To make only the background transparent use rgba() or an 8-digit hex color.

.fade { opacity: 0.5; } /* box + text fade */ .glass { background: rgba(255,161,0, 0.5); } /* only background fades */ .hidden { opacity: 0; pointer-events: none; } /* invisible but still takes space */
